# Cognitive validation: memory + operator evidence + doctrine

Entry point: `mf_dod_validation.py`. This is a **non-actuating lab harness**, not integration into the physical CognitiveOps control loop.

- Loads previously saved and reviewed proposal IDs, with the package fingerprint checked by `load_proposals`. `--approve` only selects those goals for synthetic navigation.
- Uses the previous mission JSONL to find blocked POIs. Previous journals written before this experiment may only have objective IDs; these are mapped back through saved proposals. With prior blockages and multiple approved goals, L4 may **reorder but cannot introduce or remove** any approved goal.
- Accepts optional operator-authored evidence JSON: `{"OBJ-002":{"description":"...", "observed":false, "source_ref":"operator:inspection-note-1"}}`. The source reference is a label, not a verified file. This is never generated by GPT. No evidence is inferred from synthetic arrival. `observed=true` must correspond to independently supplied actual observations; otherwise use `false` or omit.
- Optional `--pdf` points at operator-provided local doctrine PDFs. Extracted provenance includes PDF page indices; textual support of particular conclusions has **not** been validated. The same retrieved passages are supplied as untrusted contextual input when L4 reorders based on prior memory.
- Synthetic navigation generates a blocked event only with `--block-poi <POI_ID>`, otherwise arrival results, **not actual inspection evidence**.

Example after pulling the feature branch:

```bash
python -m unittest -v tests/test_mf_dod_validation.py
python -m mf_dod_validation mission_packages/llombai_sim/manifest.json \
  --load-proposals /tmp/llombai_sim_proposals.json \
  --approve OBJ-001 OBJ-002 OBJ-003 OBJ-004 \
  --prior-journal /tmp/llombai_agent_test.jsonl \
  --backend openai --allow-api --model gpt-5.4 \
  --journal /tmp/llombai_memory_validation.jsonl
```

This uses billable API calls. It only tests how L4 reasons over historical feedback. For doctrine, append e.g. `--pdf 'docs/references/fm_3-25.26_map_reading_and_land_navigation.pdf'` if it exists locally. For evidence, add `--evidence /path/to/operator_evidence.json` with a separately collected, accurately described operator record.

Caveats: `MissionJournal` is an append-only log, not a transactional memory store; replay does not verify event authenticity. This harness still needs integration with physical sensing, authentication, and a reviewed geofence with clearance margins before real-world use. `main`, L1, L2 and VisionNN are unchanged.
